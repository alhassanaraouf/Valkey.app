How to run several Valkey versions side by side on Mac

Testing an upgrade, matching what production runs, or keeping two projects apart: sometimes you need more than one Valkey server on your Mac, on different versions. Here's how to do it with Valkey.app, its command line, Homebrew and Docker.

Why run more than one?

  • Upgrades. Try your app against the next Valkey version before production moves to it.
  • Match production. Run the exact version your servers run, not whatever is newest.
  • Separate projects. Each project gets its own server, port and data, so a FLUSHALL in one doesn't touch another.

With Valkey.app (window)

In Valkey.app, every server has its own name, Valkey version, port, data directory and log.

  1. Click + (or Create Server…), name it, and pick a version, for example 7.2.16.
  2. Leave the suggested port (the next free one from 6379) or type your own.
  3. Click Create. The version is downloaded if needed, then click Start.
  4. Repeat with another version, for example 9.2.0, on another port.

Both servers show in the sidebar and the menu bar, each with its own Start/Stop, live log and Connect…. Versions… lists every Valkey release you can install and which servers use it.

With the valkey-app command

The same thing from Terminal. Install the command from Settings › Command Line › Install CLI (the Homebrew cask links it for you):

valkey-app versions                                  # what you can install
valkey-app create legacy  --version 7.2.16 --port 6380
valkey-app create current --version 9.2.0  --port 6381
valkey-app start legacy
valkey-app start current
valkey-app list

create downloads the version first if it isn't installed, and start waits until the server accepts connections. Each server keeps its data in its own directory, by default ~/Library/Application Support/Valkey/var-<port>. Pick another one with --data-dir:

valkey-app create staging-copy --version 8.1.12 --port 6382 --data-dir ~/valkey/staging-copy

Connect to any of them with its own valkey-cli, or print its URL for your app's config:

valkey-app cli legacy INFO server
valkey-app url current        # valkey://127.0.0.1:6381

To upgrade a server in place, install the newer version and run valkey-app versions install 8.0.13 and then valkey-app set legacy --version 8.0.13. Only an installed version that isn't older works, and an upgrade can't be undone, so copy the data directory first if you may want to go back.

With Homebrew

Homebrew's valkey formula installs one version at a time, and brew upgrade moves it to the newest. You can start a second server from the same binary on another port and directory:

mkdir -p ~/valkey/6380
valkey-server --port 6380 --dir ~/valkey/6380 --daemonize yes

That gives you two servers, but not two versions. For an older version you'd build it from source and manage it yourself.

With Docker

Docker handles versions well: each image tag is a version, and each container gets its own port and volume.

docker run -d --name valkey-80 -p 6380:6379 -v valkey-80:/data valkey/valkey:8.0
docker run -d --name valkey-90 -p 6381:6379 -v valkey-90:/data valkey/valkey:9.0

The cost is Docker itself: Docker Desktop (or another runtime) running in the background, and a Linux VM between your app and Valkey.

If your project already runs in containers, Docker is fine. If you just want a few versions running natively with no extra tools, Valkey.app is the shortest path.
