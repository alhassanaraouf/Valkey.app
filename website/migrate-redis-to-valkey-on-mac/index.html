How to move local development from Redis to Valkey on Mac

Valkey started as a fork of Redis OSS 7.2.4 and speaks the same protocol, so for most projects switching a Mac from Redis to Valkey means changing a port, or nothing at all. Here's how to check your Redis version, move your data and point your app at Valkey.

Will my code still work?

Almost certainly. Valkey uses the Redis protocol and commands, so Redis client libraries, redis-cli and GUI tools that support Redis connect to it unchanged. The Valkey project describes moving from Redis OSS 7.2 or earlier as "effectively an upgrade".

Check your Redis version first

redis-cli INFO server | grep redis_version
  • Redis OSS 7.2 or earlier: your data moves to Valkey 7.2 or later as is. Follow the steps below.
  • Redis CE 7.4 or later: according to the Valkey project, its data files aren't compatible with Valkey. Your client still connects, but you can't copy the data over. Start Valkey empty and re-seed it the way you'd set up a fresh dev machine.

1. Create a Valkey server next to Redis

Install Valkey.app and create a server on a free port, so Redis can keep running on 6379 while you move:

valkey-app create myapp --version 9.2.0 --port 6380
valkey-app start myapp

Or click Create Server… in the app and set the port there. (Install the valkey-app command from Settings › Command Line › Install CLI.)

2. Copy your data with replication

The lowest-effort way from Valkey's migration guide is to make Valkey a replica of Redis, let it sync, then cut it loose. This replaces anything already in the Valkey server with Redis's data.

valkey-app cli myapp REPLICAOF 127.0.0.1 6379
valkey-app cli myapp INFO replication     # wait for master_link_status:up
valkey-app cli myapp REPLICAOF NO ONE
valkey-app cli myapp INFO keyspace        # compare with: redis-cli INFO keyspace

If your Redis has a password, run this first so Valkey can log in to it:

valkey-app cli myapp CONFIG SET masterauth 'your-redis-password'

Valkey's guide also covers copying the RDB file instead. That only works if AOF is off on Valkey's first start, and Valkey.app servers save with AOF on, so replication is the simpler route here. For a handful of keys, Redis's MIGRATE command can copy them one by one.

3. Point your app at Valkey

Change the port in your app's config. Most projects read it from an environment variable:

# .env
REDIS_URL=redis://127.0.0.1:6380

valkey-app url myapp prints the URL as valkey://127.0.0.1:6380. It's the same address; if your client library only accepts redis://, keep the host and port and use that scheme. If you set a password on the Valkey server, valkey-app url myapp --show-secrets includes it.

Rather not touch your config at all? Stop Redis and move Valkey to 6379:

brew services stop redis              # or: docker stop <redis-container>
valkey-app set myapp --port 6379

Your app connects to the same address as before and gets Valkey.

4. Check it

valkey-app cli myapp PING
# PONG
valkey-app cli myapp INFO server | grep version

Run your test suite against it. When you're happy, uninstall Redis (for example brew uninstall redis) or leave it stopped.

Other ways to run Valkey

You don't need Valkey.app for any of this. brew install valkey gives you one Valkey version that also defaults to port 6379, so stop Redis first or change one of the ports. With Docker, docker run -d -p 6380:6379 valkey/valkey does the same in a container. Valkey.app adds several servers and versions side by side, official JSON and Bloom modules per server, and a live log for each, with no Homebrew or Docker. See all the ways to install Valkey on Mac.
